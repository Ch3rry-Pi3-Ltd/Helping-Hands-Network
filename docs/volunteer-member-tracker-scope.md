# Volunteer and member tracker scope

Reviewed: 7 July 2026.

Purpose: define a safe scope before considering any volunteer, therapist or
membership tracker.

This is not a system build. It is a data-minimisation and safeguarding scope so
the charity can decide whether a tracker is needed at all.

## Principle

Start with the smallest useful record. Do not collect sensitive information
unless there is a clear purpose, access control, retention rule and lawful
basis.

## Possible uses

- Maintain a current list of active volunteers or members.
- Track who is interested in Bosnia, Ukraine, current UK support or fundraising.
- Record basic membership or renewal status.
- Track training, availability or role interest.
- Know who has been contacted about a specific opportunity.

## Data to consider

| Data item | Why it might be needed | Risk level | Notes |
| --- | --- | --- | --- |
| Name | Identify volunteer/member. | Medium | Required for most records. |
| Email | Contact and updates. | Medium | Prefer charity-approved mailing approach. |
| Phone | Urgent contact or trip coordination. | Medium | Only collect if needed. |
| Role/skill area | Match people to opportunities. | Low/medium | Use broad categories. |
| Project interest | Bosnia, Ukraine, current UK support, fundraising, admin. | Low/medium | Useful for segmentation. |
| Membership status | Know who is active/current. | Low/medium | Avoid financial detail unless required. |
| Training status | Confirm readiness for certain roles. | Medium | Keep factual and limited. |
| Emergency contact | Trip or fieldwork safety. | High | Only for relevant volunteers; restrict access. |
| Health information | Travel/fieldwork support. | High | Avoid unless necessary and separately governed. |
| DBS/safeguarding checks | Role-specific compliance. | High | Record status, not unnecessary underlying detail. |

## Data not to collect by default

- Detailed health history.
- Therapy notes.
- Beneficiary information.
- Passport scans or ID documents in a general tracker.
- Bank details.
- Informal opinions about volunteers.
- Sensitive personal stories.
- Anything collected only because it “might be useful later”.

## Access model

Suggested minimum roles:

- **Viewer:** can see limited contact and role information.
- **Coordinator:** can update volunteer status and interests.
- **Safeguarding/privacy owner:** can access restricted fields if needed.
- **Technical/admin owner:** can manage the tool but should not access content
  unnecessarily.

## Retention questions

Before choosing a tool, decide:

- When does an inactive volunteer record get archived?
- When is it deleted?
- Who can request correction or deletion?
- What records must be retained for legal, insurance or safeguarding reasons?
- Where is consent or privacy-notice acknowledgement recorded?

## Tool options to consider later

Do not choose a system until the data model is agreed. Possible lightweight
options:

- spreadsheet with restricted access;
- Airtable-style database;
- charity CRM;
- membership-management tool;
- custom form plus private database.

Selection criteria:

- easy for Susan/volunteers to maintain;
- access control;
- export and backup;
- audit trail if possible;
- UK GDPR suitability;
- low cost;
- no unnecessary complexity.

## First prototype, if approved later

Start with a private spreadsheet-style structure:

| Name | Email | Role interest | Project interest | Status | Last contacted | Notes requiring review? |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

Avoid sensitive notes in the first version.

## Decision checklist

- [ ] Confirm whether a tracker is actually needed.
- [ ] Nominate data owner.
- [ ] Confirm lawful basis/privacy notice.
- [ ] Agree minimum fields.
- [ ] Agree restricted fields.
- [ ] Agree retention and deletion rules.
- [ ] Choose tool only after the above is complete.
